## [2.0.0] - 2026-07-28

Replaces the short-read-only v1.0 pipeline with a unified architecture supporting both short reads
(Illumina/Element) and Oxford Nanopore long reads, plus targeted SNP/AA variant profiling. The samplesheet
format changed (`sample,library,molecule,r1,r2,reads` in place of `sample,r1,r2`).

### Added
- Long-read (ONT) workflow: Porechop_ABI -> Filtlong -> NanoPlot + FastQC for QC, Flye for AMR-subset
  assembly. Merges into the same MultiQC report as the short-read workflow.
- Targeted SNP / amino-acid variant profiling (`--run_snp_profiling`): BWA-MEM (short reads) or minimap2
  (long reads) alignment to a user-supplied CDS reference, per-read codon extraction via pysam, MultiQC
  custom content.
- Re-sequencing support: multiple samplesheet rows sharing a `sample` name are concatenated automatically.
- Wired Filtlong's native MultiQC support (`contents: "Scoring long reads"` / `"Filtering long reads"` in
  MultiQC's own search-pattern corpus) -- the module previously discarded Filtlong's stderr entirely, so
  this QC-worthy output never reached the report. Added the log capture, channel wiring, and
  `multiqc_config.yaml` section.
- `assets/pipeline_diagram.svg` (animated) and `assets/pipeline_diagram_static.png` -- rendered from the
  author's existing `nf-metro` source (`docs/balrog_rapid.mmd`, one line per data type: Short gDNA, Short
  cDNA, Long gDNA, Long cDNA) with the `Dashboard` station and its edge removed, so it now ends at
  `MultiQC`. Replaces the earlier screen-recording-derived GIF, which still showed the now-removed
  Dashboard step.

### Removed
- All BALROG-RAPID-DASHBOARD / risk-map integration (`PREPARE_DASHBOARD`, `BALROG_RISKMAP` modules, the
  `--run_riskmap`/`--riskmap_*` params, the `riskmap` resource label, and all dashboard-collection channels
  in both workflows). The dashboard will live in its own separate branch/repo, not in the pipeline or its
  publication.

### Fixed
- Same two critical execution-blocking bugs as the v1.0 pass (`check_max()` -> `resourceLimits`; top-level
  `if`/channel-setup statements in `main.nf` moved inside `workflow {}`) -- this codebase had them
  independently and was never merged with the v1.0 fixes.
- Same stale `nextflow/main.nf` paths and `nextflow/23.10.1` Ceres module version as v1.0, plus the same
  three unpinned/personal containers (`ncbi/amr:latest`, `ebird013/bbmap:latest`, `ebird013/spades:3.15.5`)
  -- fixed identically; all of the other modules (including every new ONT/SNP module) were already pinned
  to `quay.io/biocontainers`.
- **Hardcoded personal absolute paths shipped as parameter defaults**: `kraken2_db`, `sylph_db`,
  `diamond_db`, `host_sheet`, `sylph_tax_db` pointed at Edward's personal Ceres `/90daydata/...` paths;
  `slurm_account` defaulted to `'musca'`; `--outdir` defaulted to `null` instead of `./results`. All reset
  to `null`/sensible defaults -- a fresh user's run would otherwise have silently tried to read Edward's
  private database paths.
- `run_nonpareil` default was `true` with a comment claiming "Off by default" -- comment corrected.
- Manifest/CFF version bumped to 2.0.0; `nextflowVersion` requirement bumped to `>=24.04.0`.

### Verified
- `nextflow config -profile docker` resolves cleanly; `nextflow run main.nf -profile docker` (no args)
  compiles the full script (main.nf + every workflow/subworkflow/module include) and fails only at our own
  `--sample_sheet is required` check, as expected.
- A `-stub-run` with synthetic short-read AND long-read samples completed 8 real container executions
  across both workflows: the full short-read QC chain (FastQC raw/trimmed, FASTP, BBDuk), spike-in
  removal, long-read FastQC, and the new BWA_INDEX_SNP module all completed successfully. Porechop_ABI
  crashed with SIGILL, the classic signature of an x86_64 binary's SIMD instructions failing under this
  Mac's QEMU emulation (the container is amd64-only) -- not a code fix; needs verification on a native
  amd64 host (e.g. Ceres).

## [1.0.0] - 2026-07-27

### Added
- `manifest {}` block in `nextflow.config` (name, author, homePage, version, minimum Nextflow version).
- `docker` / `singularity` / `apptainer` profiles in `nextflow.config` -- no container engine is enabled
  by default; select one explicitly with `-profile`.
- Pipeline flowchart in the README.
- `CHANGELOG.md`, `docs/usage.md`, `docs/output.md`, `CITATION.cff`.
- Minimal CI (`.github/workflows/ci.yml`) that validates the config and pipeline script on every push/PR.

### Fixed
- **Critical:** removed the custom `check_max()` Groovy function from `nextflow.config` /
  `configs/base.config`. Nextflow's modern config parser (>=24.04) rejects top-level function
  definitions, so every run failed at the config-parsing stage on any current Nextflow install.
  Replaced with the standard `process.resourceLimits` directive.
- **Critical:** moved parameter validation and channel-setup logic in `main.nf` inside the `workflow {}`
  block. Bare top-level `if` statements are no longer permitted outside a process/workflow/function by
  Nextflow's strict script parser, so the pipeline failed to compile at all.
- Stale `nextflow/main.nf` and `nextflow/configs/...` paths (leftover from an old repo layout) corrected
  to `main.nf` / `configs/...` in the README, `configs/ceres/README.md`, and the Ceres SLURM template --
  the template previously could not be copied or run as documented.
- `configs/ceres/balrog.template.slurm` requested `nextflow/23.10.1`, below the new minimum version
  required by `resourceLimits`; bumped to a `>=24.04` module (verify the exact available build with
  `module avail nextflow` on Ceres).
- Pinned `ncbi/amr:latest` to a specific dated release (`ncbi/amr:4.2.7-2026-05-15.1`) for reproducibility,
  while keeping the official NCBI image (it bundles a matching AMRFinderPlus database; a biocontainers
  swap would have shipped no database at all).
- Replaced personal `ebird013/*` Docker Hub images with pinned `quay.io/biocontainers` equivalents:
  `fastqc` (0.12.1), `spades` (3.15.5), `bbmap` (39.91, used by the BBDuk process).
- Corrected the stale `README.md` Containers table (several entries no longer matched the containers
  actually declared in the modules).

### Verified
- `nextflow config -profile docker` resolves cleanly.
- A `-stub-run` with synthetic reads completes FastQC (raw + trimmed), FASTP, BBDuk, and the Bowtie2/
  samtools spike-in removal step end-to-end, pulling and running every swapped container successfully.
  Kraken2/Sylph/Diamond/AMRFinder need real reference databases to verify further and were not exercised
  beyond confirming their containers pull and launch correctly.
